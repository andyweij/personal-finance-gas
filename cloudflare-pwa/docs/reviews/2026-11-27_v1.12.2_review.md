| N1 | 未遷移期間被拒後，本機設定會被伺服器值覆蓋 | `worker/sync.ts` 設定異動；`web/src/sync/syncEngine.ts` 的拒絕處理 | 資料庫尚未套用 migration 時儲存再平衡目標等新設定，異動被拒；用戶端依既有規則（R3）標記完整重新同步，本機設定被伺服器的預設值取代，剛設的目標消失，但畫面會顯示拒絕原因。屬預期行為，只在部署順序錯誤的短暫期間發生 | 維持「先 migrate 再 deploy」；不需改程式 |

### 新舊版本混用提醒

- v1.12.1 以前的頁面仍以「兩種模式合計 30 條」正規化再平衡規則。使用者在新版設了超過 30 條後，若舊版頁面在衝突合併或本機覆蓋時正規化並送出設定，可能把規則截回 30 條。只發生在舊頁面尚未重新整理的短暫期間，重新整理後即恢復。
- 每次儲存任何設定都會送出整份設定。規則上限提高到每種模式 100 條後，設定的資料量最多約數十 KB，仍在可接受範圍。

## 確認沒有問題的部分

- **伺服器拒絕邏輯**：只在「欄位不存在」且「payload 帶有非預設值」時拒絕；舊版用戶端只改預算等其他設定時，payload 中這些欄位為空值或預設值，不會被誤拒。
- **匯入**：改為依欄位是否存在動態組 SQL，未遷移時可匯入不含新設定的舊備份，含新設定時明確失敗。
- **測試**：新增測試涵蓋「0018 之前的資料庫拒絕非空目標」「匯入同樣拒絕」「每種模式各自計算上限」「已無持股標示與排除未設目標」「當年度月均與歷史匯率」「近 12 月日曆篩選」。
- **XSS 與事件**：新增的提示、按鈕與標籤都用 `textContent` 建立，監聽器掛在每次重繪會重建的元素上。

## 部署注意事項

1. 本版沒有新的 migration。若正式環境尚未套用 0018～0020，仍須先 `npm run db:backup:remote`、`npm run db:migrate:remote`，再 `npm run deploy`。
2. 本版之後，部署順序錯誤不再造成無聲遺失，而是明確拒絕並提示執行 migration。
3. v1.12.0 的高嚴重度問題（匯率自動更新後，匯率設定視窗存不了檔）已於 v1.12.3 修正，並一併修正再平衡目標比例輸入框的同類問題，詳見 [`2026-11-27_v1.12.0_v1.11.1_review.md`](./2026-11-27_v1.12.0_v1.11.1_review.md)。
