## 獨立審查與後續修正

| 嚴重度 | 問題 | 處理 |
|---|---|---|
| 中 | 多分頁：分頁 B 確認更新後，分頁 A 仍以舊程式碼在新 SW 底下執行；A 的提示按了也沒反應（已重現） | 載入時記下是否已有 controller，之後的 `controllerchange` 若不是第一次安裝，就把提示改為「新版本已在其他分頁啟用，請重新整理」。按鈕發現 worker 已經 `activated`／`redundant` 時直接重新整理。端對端測試加入這個情境 |
| 中 | 開發伺服器：dev 版 SW 會把 `/src/*.ts` 永久快取（已重現） | 只有正式建置才註冊 SW（`import.meta.env.PROD`）；未建置的 `sw.js`（佔位字串仍在）也一律不攔截請求 |
| 低 | 停在登入畫面時看不到更新提示 | 提示加入登入遮罩的保留清單，只在鎖定畫面時隱藏 |
| 低 | 在 `load` 之前就開始安裝的新版，`updatefound` 會漏接 | 註冊後也追蹤 `reg.installing` |
| 低 | Workers Static Assets 的 SPA fallback 會以 index.html 200 回應不存在的檔案，可能被存到 JS／CSS 網址底下 | 安裝與執行期快取都拒絕「`.js`／`.css` 網址卻是 `text/html`」的回應；安裝失敗時目前的版本繼續運作。安裝改以 `cache: 'reload'` 逐一抓取 |
| 低 | 從舊版 SW 升級時，可能有一次白畫面，而且要開兩次才看到提示 | 這是舊版 SW（快取優先＋SWR）本身的行為，無法由新版修正，見「行為變更」 |

審查確認沒有問題的部分：
- 從 v33 升級後不會卡在舊版，也不會新舊混用。
- 第一次安裝不會造成重新載入迴圈。
- `/index.html` 轉址到 `/` 不影響（預快取只有 `/`）。
- `/api/*` 與 `/sw.js` 一律走網路。
- CSP 與 `_headers` 不受影響，提示以 DOM 建立，沒有 inline 腳本。
- 建置外掛的排除清單、路徑分隔符與佔位檢查正確。
- 舊快取只清除 `finance-pwa` 開頭的快取。

## 行為變更

- **有新版本時會顯示「有新版本可以使用」提示**，按「立即更新」才會切換並重新載入；按「稍後」則下次開啟時再提示。關閉所有分頁後再開啟，也會直接是新版。
- **從 v1.8.13 以前升級的第一次**：舊版 SW 仍會先提供舊頁面，可能需要再開一次 app 才會出現提示。極少數情況（舊版安裝後只開過一次）會看到空白頁，重新整理一次即可。
- 開發模式（`npm run dev:web`）不再註冊 Service Worker。
- 說明頁的「離線快取」欄位顯示 `finance-pwa（每次建置自動更新）`。

## 仍未處理

- 每次建置的 hash 都會不同（`__BUILD_TIME__` 精確到分鐘），所以每次部署都會出現一次更新提示；這是預期的行為。

## 部署

不需要 migration。執行 `npm run deploy`（會先 `build:web`，由外掛產生 `sw.js`）。部署後可在瀏覽器開發者工具的 Application → Cache Storage 確認快取名稱為 `finance-pwa-<hash>`，且清單中沒有含 `?` 的網址。
