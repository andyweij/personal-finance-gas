# v1.13.1 修改紀錄：固定收支可設定每月入帳日

- **migration**：`0022_recurring_post_day.sql`（`recurring_items.post_day INTEGER NOT NULL DEFAULT 1`）
- **部署順序**：`npm run db:backup:remote` → `npm run db:migrate:remote` → `npm run deploy`

## 背景

固定收支的自動入帳（每月 1 日的排程，以及「立即入帳本月」按鈕）原本把流水帳一律記在當月 1 號。

活存帳戶的餘額是「基準餘額 ＋ 存轉 ＋ 連動的流水帳」，而**基準生效日之前的流水帳不計入**（避免重複扣減）。因此：

- 使用者在月中校正過活存餘額（例如 11/20），之後才入帳本月的固定收支，這些記在 11/01 的流水帳都在基準日之前，不會影響餘額。
- 若實際入帳在校正之後（例如薪資 11/25 才進來），餘額就會少算。

## 修改內容

### 資料與共用邏輯

- `shared/types.ts`：`RecurringItem.postDay?: number`。
- `shared/recurring.ts`：
  - `normalizeRecurringPostDay`：缺漏或無效的值一律視為 1（維持舊行為）。
  - `resolveRecurringEntryDate(yearMonth, postDay)`：該月沒有這天時記在月底（31 → 11/30、2 月 → 28 或 29）。
- `shared/validation.ts`：`validateRecurringInput` 接受 1～31 的整數，其餘回傳「入帳日需為 1～31 的整數。」；未提供時為 1。

### 伺服器

- `worker/automation.ts`：自動入帳的流水帳日期改為 `resolveRecurringEntryDate(yearMonth, item.post_day)`。去重鍵仍是「項目 + 月份」，不會因為改入帳日而重複入帳。
- `worker/sync.ts`：
  - 讀取：`mapRecurringRow` 帶回 `postDay`。
  - 寫入：v1.13.1 以前的客戶端不會送 `postDay`，此時**保留資料庫中原本的入帳日**，不會被改回 1 號。
  - 未套用 0022 時：非預設入帳日以 `RejectError` 明確拒絕（比照 v1.12.2 的做法）；預設 1 號不寫入這個欄位，照常成功。新增項目時只有入帳日不是 1 號才多一次欄位檢查查詢。
  - 備份匯入：有欄位時一併寫入與更新；未遷移且備份含非預設入帳日時明確失敗。

### 用戶端

- `web/src/ui/configTab.ts`：固定收支編輯視窗新增「入帳日（每月幾號，1～31；該月沒有這天則記在月底）」；列表在入帳日不是 1 號時顯示「N 日入帳」。
- `web/src/sync/syncEngine.ts`：
  - `saveRecurring`：呼叫端沒有帶 `postDay`（例如切換啟用狀態）時沿用既有值。
  - 從記帳勾選「加入每月常態」建立的項目，入帳日沿用該筆記帳的日期。
- `web/src/ui/conflictUi.ts`：衝突畫面顯示「入帳日」。
- 版本：`package.json`、`web/src/version.ts` 改為 1.13.1，`DB_SCHEMA_VERSION` 改為 `0022`；`docs/DATABASE_SCHEMA.md` 同步更新。

## 行為說明

- **既有項目**：入帳日都是 1 號，入帳結果與之前完全相同。
- **入帳時機不變**：排程仍在每月 1 日入帳整個月份；入帳日只決定流水帳的日期。入帳日在未來的流水帳（例如 11/01 入帳、日期 11/25），在活存餘額中**入帳當下就會計入**，與手動記一筆未來日期的流水帳相同。
- **已入帳的流水帳不會被改動**：修改入帳日只影響之後才入帳的月份。

## 測試

新增 `tests/recurring-post-day.test.ts`（12 項）：

- 共用函式：一般日期、月底調整、閏年；缺漏或無效值視為 1；驗證範圍。
- 自動入帳記在入帳日、預設項目仍記在 1 號、31 號在 11 月記在月底、重跑不重複。
- 連動活存：入帳日晚於基準日時計入餘額，1 號的項目被基準日排除。
- 舊版客戶端不帶 `postDay` 時保留原入帳日；同步拉取帶回 `postDay`；備份匯出再匯入保留入帳日。
- 未套用 0022：非預設入帳日被拒、預設 1 號照常寫入、自動入帳記在 1 號；匯入含非預設入帳日時失敗、全部 1 號時可匯入。
- 用戶端：切換啟用狀態保留入帳日；「加入每月常態」沿用記帳日期。

暫時還原 `worker/automation.ts` 的改動時，入帳日期與連動活存 2 項會失敗，確認測試有效。
