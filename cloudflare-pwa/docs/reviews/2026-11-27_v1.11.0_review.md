## 發現（依嚴重度排序）

### 1. 中：類型為「固定收入」或「訂閱扣款」的範本，套用時會被改記成「日常花費」

- **位置**：
  - `web/src/ui/quickTemplatesUi.ts` 的範本編輯器：類型選單列出全部 `ALL_CASHFLOW_TYPES`（7 種）。
  - 同檔套用範本（填入表單模式）：`ctx.state.logType = QUICK_ENTRY_TYPES.includes(tpl.type) ? tpl.type : '日常花費'`。`QUICK_ENTRY_TYPES` 只有 5 種，不含「固定收入」與「訂閱扣款」。
- **觸發條件**：建立類型為「固定收入」的範本，分類選「其他」，不開「一鍵直記」，然後點這個範本。
- **影響**：
  - 記帳表單的類型變成「日常花費」，分類仍是「其他」（日常花費也有這個分類，所以不會跳掉），畫面上沒有任何提示。使用者送出後，收入被記成支出。
  - 若開了一鍵直記，則以快速記帳表單本身不開放的類型直接入帳，與表單的限制不一致。
- **建議修法**：範本編輯器的類型選單只列 `QUICK_ENTRY_TYPES`；套用時遇到不在清單內的類型，顯示錯誤並中止，不要改成日常花費。
- **重現**：子代理以暫時測試確認 `validateQuickTemplateInput` 接受「固定收入」；套用路徑經程式碼確認。

### 2. 中：自動補齊會帶入其他類型的分類和金額

- **位置**：
  - `shared/autocomplete.ts` 的 `buildAutocompleteSuggestions`：`opts.type` 只用來加權排序（`typeBoost`），不過濾。建議的分類取「最常出現」的分類，類型卻取「最近一次」的類型，兩者可能對不上。
  - `web/src/ui/quickTemplatesUi.ts` 點選建議時：直接設定 `ctx.state.logCategory = s.category`，金額欄為空時帶入 `s.suggestedAmount`。
- **觸發條件**：在「日常花費」下輸入「年」，建議清單出現過去記為「其他收入／獎金／50000」的項目，點選它。
- **影響**：`renderLogCategories` 發現「獎金」不屬於日常花費，悄悄改回第一個分類「餐飲」，金額卻照樣帶入 50000。已刪除的自訂分類也會發生同樣的跳回。
- **建議修法**：建議清單依目前類型過濾；或點選時檢查分類是否在 `getEffectiveCategoriesForType(目前類型)` 內，不在就不要改分類和金額。
- **重現**：子代理以暫時測試確認會回傳其他類型的建議；點選路徑經程式碼確認。

### 3. 中：先部署程式碼、後跑 migration 時，新設定會無聲遺失（延續 v1.10.0 發現 1）

- **位置**：`worker/sync.ts` 的 `applySingleMutation`（`entity === 'settings'`）。原本只對 `rebalance_targets_json` 做「欄位不存在就略過」，本版改為對 `rebalance_targets_json`、`custom_categories_json`、`quick_templates_json` 三個欄位逐一判斷，缺哪個就不寫哪個，仍然回 ack。
- **觸發條件**：先 `npm run deploy`，再 `db:migrate:remote`；中間這段期間使用者儲存再平衡目標、自訂分類或範本。
- **影響**：
  - 伺服器回成功但沒有寫入，下次拉取時 `mapAppSettingsRow` 回傳空值，用戶端的設定被清空，沒有任何提示。
  - `importFullSnapshot` 固定寫入這三個欄位，同一期間匯入備份會直接失敗。
- **建議修法**：部署時嚴格依照「migrate → deploy」；程式面把略過改成拒絕這筆異動（RejectError，提示伺服器尚未升級）。
- **重現**：依程式碼確認，未在 workerd 實測。

### 4. 中低：一鍵直記的範本，綁定帳戶不存在時改從預設活存扣款

- **位置**：`shared/autocomplete.ts` 的 `resolveQuickTemplateForEntry`；`web/src/ui/quickTemplatesUi.ts` 的一鍵直記路徑。
- **觸發條件**：範本綁定的活存帳戶被刪除（或不屬於範本的帳本），使用者點一鍵直記。
- **影響**：一鍵直記不經使用者確認，直接以 `defaultSavingsId`（預設活存，沒有就取該帳本第一個活存）入帳。錢從另一個帳戶扣，只在 toast 附註「原綁定帳戶已異動，已自動切換」。
- **建議修法**：一鍵直記遇到 `fallbackAccount` 或 `fallbackLedger` 時中止並提示使用者編輯範本；只在「填入表單」模式下自動替換，讓使用者送出前看得到。
- **重現**：依程式碼確認。

## 確認沒有問題的部分

- **migration 0019**：兩個 `ADD COLUMN ... NOT NULL DEFAULT`，可直接套用在既有資料上，不需重建資料表。
- **D1 查詢預算**：設定異動仍是一次 `SELECT *` 加一次 UPDATE，沒有新增查詢。
- **伺服器不限制流水帳分類**：`validateCashFlowInput` 對分類只做長度截斷，自訂分類不會被伺服器拒絕，新舊客戶端都相容。
- **新舊客戶端混用**：舊版 `LocalFinanceDB` 以 `...raw.settings` 保留整個設定物件；`syncEngine.ts` 的衝突合併與本機覆蓋兩處都已加入 `customCategories`、`quickTemplates`；`conflictUi.ts` 補上欄位名稱。
- **輸入正規化**：`normalizeCustomCategories` 只接受有效類型、截斷長度、去除重複、排除與內建分類同名者，每類最多 30 個；`normalizeQuickTemplates` 檢查類型、幣別、金額，截斷字串長度，最多 30 筆。
- **匯入備份**：取代模式下，備份沒有這兩個欄位時清為空值；合併模式沿用目前值。
- **XSS**：分類名、範本名、項目、備註、自動補齊建議都用 `textContent` 或 `option.textContent` 輸出；`innerHTML` 只用來清空容器。
- **事件綁定**：`bindQuickTemplatesAndAutocompleteEvents` 只在 `bindEvents` 呼叫一次，沒有 document 或 window 層級的監聽；每次重繪重建元素再綁定，不會累積。
- **內建分類**：UI 沒有刪除鈕，與內建分類同名會被擋下；分類被刪除後，舊流水帳保留原分類，編輯視窗會把缺少的分類補回選單。
- **範本參照已刪除的資料**：已刪除的帳本或活存帳戶都有退回處理（一鍵直記的問題見發現 4）；套用範本不會覆蓋日期；USD 會更新匯率預覽。
- **一鍵直記與範本編輯器**：一鍵直記有 `oneClickBusy` 防連點與 try/catch；範本編輯器用 `bindSubmit` 加 try/catch，會顯示驗證訊息。
- **切換帳號與重繪**：自動補齊每次讀取目前的 `ctx.engine`；只重繪可見分頁；切換帳號時重設 `activeLedgerId` 與 `logLinkedAccountTouched`。
- **行動裝置點選建議**：`mousedown` 取消預設行為，blur 延遲 160 ms 才關閉清單，點選時機應正確（未實機驗證）。
