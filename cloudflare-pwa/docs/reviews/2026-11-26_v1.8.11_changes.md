## 獨立審查後的修正

修正完成後另以獨立審查（含在本機 `wrangler dev` 上實際執行 Worker）檢查，發現並已修正：

| 嚴重度 | 問題 | 修正 |
|---|---|---|
| **阻擋上線** | CSRF 檢查以 `req.body !== null` 判斷是否有 body；**在 Cloudflare 實際執行環境中，沒有 body 的 POST（`Content-Length: 0`）`req.body` 仍不是 null**，導致登出、Passkey 註冊、手動更新報價、月底快照、作廢邀請碼全部回 415。最嚴重的是登出：伺服器 session 沒有撤銷，本機資料刪除、重新載入後又自動登入。測試沒抓到是因為 Node 測試環境的行為不同 | 只依 `Content-Length` / `Transfer-Encoding` 判斷；新增以 `Content-Length: 0` + 空串流模擬 workerd 的回歸測試（還原舊寫法時確認會失敗） |
| 中 | 登出請求失敗（離線或 5xx）時，本機資料已刪除但伺服器 session 與 cookie 仍有效，下次上線會自動登入 | `logoutSession` 回傳伺服器是否確認；失敗時記錄「待完成的伺服器登出」，下次啟動在顯示任何內容前先完成登出，完成前只顯示登入畫面 |
| 中 | 每個帳號的登入總額度在驗證前就遞增，單一 IP 即使已被擋，仍可持續消耗額度把真正的使用者鎖在外面 | 帳號總額度改為「只計算密碼驗證失敗」：驗證前只讀取、密碼錯誤才計數；新增測試 |
| 中 | 其他分頁仍是舊版程式時，刪除資料庫會被擋住，登出永遠停在載入中 | 被擋超過 3 秒就繼續並提示「請關閉其他分頁」，刪除會在其他分頁關閉後完成 |
| 中 | 切到背景就關閉開啟中的表單並上鎖：複製 OTP、選擇匯入檔案都會中斷 | 切到背景時立即隱藏畫面（多工畫面看不到金額），但**超過 30 秒**才上鎖，且不再關閉表單 |
| 低 | 遮罩時只隱藏頁首、內容與導覽列，modal 與計算機仍可見、可操作 | 隱藏並 `inert` 頁面上除登入 / 鎖定畫面以外的所有元素 |
| 低 | toast 改到登入畫面之下後，登入畫面上的提示（例如「密碼已重設完成」）看不到 | toast 恢復在登入畫面之上，只在鎖定畫面開啟時隱藏 |
| 低 | 伺服器延長 session 時沒有重發 cookie，瀏覽器的 cookie 仍在登入 30 天後過期 | 延長時一併重發 cookie，`Max-Age` 為剩餘可用時間（不超過 90 天上限）；新增測試 |
| 低 | 只開 Face ID 鎖、Passkey 又無法離線驗證時，離線狀態下無法解鎖 | 設定畫面提示建議同時設定 PIN 作為備援 |
| 低 | `sync_idempotency` 30 天就清除，離線很久的裝置重送時會出現假衝突 | 改為保留 90 天 |

審查確認沒有問題的部分：原子限速 SQL 在 D1 上的行為（遞增、視窗重置、成功清除）；`_headers` 確實輸出並由 `wrangler dev` 回應；CSP 與 app 相容（沒有 inline 腳本、`eval`、外部資源；blob 下載、data URI、WebAuthn、Service Worker 都正常）；`Origin: null` 與同站子網域都會被拒絕；網頁客戶端所有帶 body 的請求都是 JSON；沒有其他未跳脫的 `innerHTML`。

## 行為變更（請注意）

- **登出會刪除這台裝置上的帳本資料**，下次登入會從雲端重新下載。有未同步的變更時會先詢問。
- **伺服器可連線但登入已失效時，必須重新登入**，不再能直接檢視本機快取。
- **設定 PIN / Face ID 鎖定時，切到背景會立即隱藏畫面，離開超過 30 秒回來需要解鎖。**
- **非 ES256 的 Passkey**（例如部分 Windows Hello）無法再離線解鎖，請改用 PIN。
- **管理員以重置碼重設成員密碼後**，該成員需要重新註冊 Passkey 與設定 PIN。
- 所有有 body 的 API 請求都必須是 `application/json`；網頁客戶端原本就是如此。

## 仍未處理

- **B5（PIN 雜湊下發客戶端）**：根本解法是改由伺服器驗證 PIN，並為離線解鎖改用每台裝置各自的驗證資料（或以 PIN 衍生金鑰加密本機資料），屬於較大的重新設計，本次未做。目前已加上 UI 層的嘗試次數限制，但拿得到 IndexedDB 或 `/api/auth/status` 回應的人仍可離線暴力破解 4～6 位數 PIN。
- **本機資料未加密**：鎖定畫面仍是 UI 層保護，資料以明文存在 IndexedDB。
- 第 2～5 組（資料正確性、資源上限與排程、Service Worker、架構）尚未開始。

## 部署

1. `npm run db:backup:remote`
2. `npm run db:migrate:remote`（套用 `0014`、`0015`）
3. `npm run deploy`
4. 部署後確認頁面回應帶有 `Content-Security-Policy` 標頭（瀏覽器開發者工具 → Network → 文件請求），並實際操作一輪：登入、記帳、Face ID / PIN 解鎖、匯入 CSV、匯出、登出，確認 CSP 沒有擋掉任何功能。
