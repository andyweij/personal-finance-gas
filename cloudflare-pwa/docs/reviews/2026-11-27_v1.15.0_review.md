## 發現

### 1. 高：對帳校準後，當天在校準前的刷卡被重複計入未繳金額

- **位置**：`web/src/sync/syncEngine.ts` 的 `saveAssetInner`：

  ```ts
  const balanceAnchorAt = v.isLinkedSavings ? v.balanceAnchorAt ?? existing?.balanceAnchorAt ?? nowIso : null;
  ```

  只有活存帳戶保留 `balanceAnchorAt`，信用卡一律存成 null。`reconcileCreditCard` 傳入的 `balanceAnchorAt: nowIso`，以及卡片編輯視窗帶的值，都被丟掉。
- **原因**：餘額計算以「基準日 + 基準時間」判斷哪些交易已包含在基準餘額中。基準時間為 null 時，基準日當天的交易全部視為「基準之後」，於是再計入一次。
- **觸發條件**：在有刷卡的當天做對帳校準（校準日預設就是今天），或在當天編輯卡片並修改餘額。
- **影響**：當天在校準前的刷卡被重複計入，未繳金額偏高；這不是暫時現象，之後也會一直偏高。重現：11/27 刷 1,000，隨即校準未繳為 1,000，結果顯示 2,000。
- **建議修法**：`saveAssetInner` 對信用卡（`isCreditCard`）比照活存保留 `balanceAnchorAt`；卡片編輯視窗比照 `assetsTab.ts` 的活存規則帶入基準時間。
- **重現**：`tests/v1150-review.test.ts`「發現 1」（`it.fails`）。

### 2. 中高：分期期數漏入帳

- **位置**：`worker/automation.ts` 的 `runMonthlyInstallmentsD1` 與 `runScheduledAutomation` 的 catch-up；`web/src/sync/syncEngine.ts` 的 `saveInstallmentPlan`（`postFirstNow`）與 `postDueInstallmentsForMonth`。
- **原因**：
  - 伺服器排程與前端「入帳本月分期」都只入帳「指定月份那一期」（`seq = 起始月份到該月的月數 + 1`），不會補上之前漏掉的期數。
  - 入帳後 `posted_installments = MAX(posted_installments, seq)`，計數直接跳到當期，漏掉的期數被當成已入帳。
  - 排程以 `automation_runs`（使用者 × `installments` × 月份）標記當月已完成；之後同月新建的分期，排程不會再處理。
- **觸發條件與影響**（皆已重現）：
  - **起始月份在過去**：例如 9 月起 6 期、11 月才登記，「已入帳期數」填 0。結果只入帳第 3、4 期（11、12 月），第 1、2 期永遠不會入帳，`posted_installments` 卻變成 4。勾選「立即入帳第 1 期」時也只多入第 1 期，第 2 期仍然漏掉。
  - **月中建立、當月開始，且取消勾選「立即入帳第 1 期」**：當月排程已標記完成，第 1 期被跳過，下個月直接從第 2 期開始。預設是勾選的，所以要取消勾選才會發生。
  - 漏掉的期數不會出現在任何消費或信用卡未繳金額中；進度顯示的「已入帳期數」卻包含它們，剩餘期數因此被低估。
- **建議修法**：
  - 入帳時補上 `posted_installments + 1` 到當期之間所有未入帳的期數（伺服器排程與前端都要改），或在建立時依起始月份補入到本月為止的期數。
  - 「已入帳期數」語意改為「開始記帳前已繳的期數」，排程從它的下一期開始補。介面依起始月份預填，或提示使用者確認。
  - 排程的「本月已完成」不要擋下之後新建的計畫，例如改以「每筆計畫的 posted_installments 是否已到當期」判斷。
- **重現**：`tests/v1150-review.test.ts`「發現 2」（`it.fails` 2 項）；對照組「當月建立、逐月入帳不漏期」為 `it`。

### 3. 中：外幣卡或外幣扣款帳戶的繳款預設金額，幣別放錯

- **位置**：`web/src/ui/creditCardUi.ts` 繳卡費視窗的 `defaultPayAmt`。
- **原因**：`payCreditCardBill` 把金額當作**扣款帳戶**的幣別處理（跨幣別時再換算成卡片幣別沖銷）。但預設值在台幣卡時填 `billedUnpaidTwd`，外幣卡時填 `currentBalanceNative`（卡片幣別），都沒有依扣款帳戶的幣別換算。
- **觸發條件**：卡片與扣款帳戶幣別不同。例如美元卡欠 100 USD，從台幣活存繳款，預設金額是 100，送出後只扣 NT$100、沖銷約 3.1 USD；反過來，台幣卡從美元帳戶繳款，台幣數字會被當成美元扣款。切換扣款帳戶時，預設金額也不會重算。
- **影響**：使用者照預設值送出就會繳錯金額；活存帳戶不檢查餘額，會直接扣下去。
- **建議修法**：先依卡片幣別算出應繳金額，再以匯率換成所選扣款帳戶的幣別；扣款帳戶變更時重新計算。
- **同一處的相關問題**：台幣卡「本期已出帳未繳」為 0 時，預設金額改成「全部未繳」（含未出帳），與畫面說明「本期已出帳未繳」不一致；外幣卡一律預設全部未繳。

### 4. 中：刪除信用卡、刪除分期沒有確認，刪卡也不檢查進行中的分期

- **位置**：`web/src/ui/creditCardUi.ts` 的「刪除此信用卡帳戶」與分期列的「刪除」按鈕。
- **問題**：專案其他刪除動作都會先 `confirm()`，這兩處點一下就刪。刪除信用卡時也不檢查綁定的進行中分期；這些分期之後每月照樣入帳到已刪除的卡片 id，消費有記，但不會出現在任何卡片的未繳金額中。
- **建議修法**：加上確認；卡片有進行中的分期時警告，或要求先轉移或結清。

### 5. 中低：刷卡記帳的卡片沒有串到範本、帳戶篩選與名稱顯示

- **範本**：「存成範本」會把卡片 id 帶進範本，但範本編輯視窗（`quickTemplatesUi.ts`）只列活存帳戶，存檔時悄悄變成「不連動」；`resolveQuickTemplateForEntry` 遇到卡片 id 也會退回預設活存，等於把刷卡改成從活存扣款。
- **流水帳**：`logTab.ts` 的帳戶篩選與名稱對照只列活存，刷卡紀錄看不出是哪張卡，也無法依卡片篩選。
- **建議修法**：範本與篩選的帳戶清單一併列出信用卡；`resolveQuickTemplateForEntry` 接受信用卡 id。

## 確認沒有問題的部分

- **記帳邏輯**：刷卡記帳的 `linkedAccountId` 指向卡片，不扣活存，消費只計入一次；繳卡費以存轉沖銷，不另產生消費紀錄。
- **migration 0024**：
  - `automation_runs` 沒有被其他表參照，重建時資料完整搬移。
  - 新增的分期唯一索引只套用在未刪除且有分期欄位的流水。
  - 新表 `installment_plans` 使用複合主鍵且沒有 `DEFAULT 'owner'`，符合 v1.8.16 的慣例。
- **伺服器同步**：分期計畫的卡片與帳本參照都經 M3 檢查；未遷移時有回退處理。
- **排程**：分期入帳以「計畫 + 期數」去重，並以唯一索引保護，重跑不會重複；每處理一筆計畫前檢查 D1 查詢預算。
- **帳單週期**：結帳日超過該月天數時調成月底；跨年以月份位移處理；繳款截止日在結帳日之後落在同月，否則落在下個月。
- **輸入與錯誤處理**：
  - 金額欄位都是 `step="any"`，日、期數欄位是整數 step，不會再出現 v1.12.0 那種瀏覽器擋下存檔的問題。
  - 各存檔、繳款按鈕都有 `bindSubmit`、try/catch 與 toast；刪除與入帳按鈕有防連點。
- **XSS 與事件**：使用者字串一律用 `textContent`；沒有新增 document 或 window 層級的事件綁定。
- **日期**：一律用 `todayInTimeZone`（台北時區）。

## v1.16.1 修正（發現 1、2）

PR #17 的版本號因先後合併 v1.15.0、v1.16.0，由 1.14.1 → 1.15.1 → **1.16.1**；以下修正與 v1.8.17 審查的修正同版發布。

### 發現 1：對帳校準重複計入當天刷卡

- `web/src/sync/syncEngine.ts` 的 `saveAssetInner`：信用卡（`isCreditCard`）比照活存保留 `balanceAnchorAt`。`reconcileCreditCard` 帶入的校準時間因此保存下來，當天在校準前的刷卡不再被重複計入。
- `web/src/ui/creditCardUi.ts` 的卡片編輯視窗：新增 `resolveCardAnchorAt`，規則與活存相同：
  - 基準日在過去：以該日 00:00 為基準時間。
  - 基準日與基準餘額都沒變：保留原本的基準時間。
  - 其他情況：以現在為基準時間。
  - 原本一律沿用舊的基準時間或現在，與修改後的餘額不一致。
- 伺服器的驗證本來就保留 `balanceAnchorAt`，不需修改。
- 既有資料：已存成 null 的卡片維持原狀，下次編輯或校準時寫入正確的基準時間。

### 發現 2：分期期數漏入帳

- **伺服器**（`worker/automation.ts`）：
  - `runMonthlyInstallmentsD1` 改為補入「`posted_installments` + 1」到當期為止所有未入帳的期數，每期之前檢查 D1 預算。
  - 補入的期數 `year_month` 記在該期自己的月份（原本會記成目前處理的月份）。
  - 當期已入帳時仍計為略過一次，維持原本的重跑語意。
- **排程**：catch-up 不再以「本月 installments 已完成」擋下，改以 SQL 找出「仍有到期未入帳期數」的使用者（`posted_installments` 小於起始月份到本月的月數 + 1）。之後同月新建的計畫會在下一次排程入帳；沒有待入帳期數的使用者不增加查詢。
- **用戶端**（`web/src/sync/syncEngine.ts`）：
  - 新增 `buildInstallmentCashflows`、`installmentKeysInSnapshot`。
  - `saveInstallmentPlan` 勾選「立即入帳」時，補入到本月為止的所有期數；首期在未來時維持入帳第 1 期。
  - `postDueInstallmentsForMonth` 同樣補入漏掉的期數，且每筆計畫只送一個原子群組：所有補入的流水，加上一筆最終的計畫更新，避免同一計畫多次更新造成版本衝突。
- **介面**：「已入帳期數」標示為「開始記帳前已繳的期數」；「立即入帳」說明改為「立即入帳到本月為止的期數」。

## v1.16.2 修正（發現 3～6）

### 發現 3：繳卡費預設金額的幣別

- 新增 `shared/creditCard.ts` 的 `computeDefaultCardPayment`：
  - 應繳金額：本期已出帳未繳；沒有已出帳金額時為全部未繳，以卡片幣別計算，且不超過全部未繳。
  - 再依目前匯率換成扣款帳戶的幣別，同時回傳要沖銷的卡片幣別金額。
- `web/src/ui/creditCardUi.ts` 繳卡費視窗：
  - 預設金額改由此函式計算。
  - 切換扣款帳戶時，若使用者尚未手動修改金額，就重新計算。
  - 金額欄標示扣款帳戶幣別。
  - 跨幣別且金額未修改時，沖銷欄直接帶入應繳的卡片幣別金額，避免來回換算的捨入誤差。
- 測試：
  - 美元卡欠 100 USD 從台幣帳戶繳：預設 NT$3,200、沖銷 100 USD（修正前預設 100）。
  - 台幣卡已出帳 NT$3,200 從美元帳戶繳：預設 100 USD。
  - 另有台幣卡、外幣卡已出帳且不超過未繳、沒有未繳等案例。

### 發現 4：刪除沒有確認

- 刪除信用卡：卡片仍有進行中的分期時擋下並提示先提前清償或刪除分期；否則以 `confirm()` 確認，並說明已記錄的刷卡流水會保留。
