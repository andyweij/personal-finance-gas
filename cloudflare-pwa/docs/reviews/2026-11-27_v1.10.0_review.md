## 發現（依嚴重度排序）

### 1. 中：先部署程式碼、後跑 migration 時，再平衡目標會無聲遺失

- **位置**：`worker/sync.ts` 的 `applySingleMutation`（`entity === 'settings'`）。程式以 `'rebalance_targets_json' in existingRow` 判斷欄位是否存在；不存在時改用不含該欄位的 UPDATE，照樣回 ack。
- **觸發條件**：先執行 `npm run deploy`，再執行 `db:migrate:remote`。在這段期間，使用者用新版頁面儲存再平衡目標。
- **影響**：
  - 伺服器回成功，但目標沒有寫入。下次拉取時 `mapAppSettingsRow` 回傳 `rebalanceTargets: []`，用戶端的目標被覆蓋清空，沒有任何錯誤提示。
  - `importFullSnapshot` 的 UPDATE 沒有同樣的後備，固定寫入 `rebalance_targets_json`。同一段期間內匯入備份會直接失敗，兩條寫入路徑的行為不一致。
- **建議修法**：
  - 部署時嚴格依照「`db:migrate:remote` → `deploy`」的順序（見文末）。
  - 程式面把後備改成拒絕這筆異動（RejectError，提示伺服器尚未升級），或在 payload 帶有 `rebalanceTargets` 時拒絕，不要靜默略過。
- **重現**：依程式碼確認，未在 workerd 實測。

### 2. 中：規則總數上限 30 條，導致存檔失敗，且錯誤訊息和畫面矛盾

- **位置**：
  - `shared/validation.ts` 的 `normalizeRebalanceTargets`：`if (out.length >= 30) break`，上限由「依分類」與「依標的」兩種模式共用。
  - `web/src/ui/rebalanceUi.ts` 的存檔：`validateRebalanceTargetsForSave([...otherKindRules, ...newKindRules])`，另一模式的舊規則排在前面。
- **觸發條件**：
  - 已有 25 條「依標的」規則，再設 10 個分類各 10%：跳出「分類目標比例合計需為 100%（目前為 50.0%）」。
  - 只用「依標的」模式設 35 檔個股：跳出「目前為 85.8%」。
- **影響**：持股超過 30 檔的使用者無法以「依標的」存檔。兩種模式合計超過 30 條時，後設的模式會被截斷。視窗上方顯示合計「100% ✓」，錯誤訊息卻是 50%，使用者無從理解原因。
- **建議修法**：上限改成每個模式各自計算（或提高上限），並在 UI 存檔前檢查條數，超過時明確說明是條數超過上限。
- **重現**：子代理以 vitest 實測兩種情境；本報告另以程式碼確認截斷與合併順序。

### 3. 中低：「清除此模式目標」沒有錯誤處理

- **位置**：`web/src/ui/rebalanceUi.ts` 中 `clearBtn` 的 click handler。
- **問題**：直接 `await ctx.engine.saveRebalanceTargets(...)`，沒有 try/catch，也沒有經過 `bindSubmit` 防止連點。
- **影響**：`saveRebalanceTargets` 會再跑一次驗證；多分頁同時寫入、重試仍失敗時也會 throw。失敗時成為 unhandled rejection，沒有 toast，視窗也不會關閉。
- **建議修法**：比照「儲存目標比例」包 try/catch 並顯示錯誤 toast，執行期間停用按鈕。
- **重現**：依程式碼確認。

## 確認沒有問題的部分

- **migration 0018**：`ALTER TABLE app_settings ADD COLUMN rebalance_targets_json TEXT NOT NULL DEFAULT '[]'` 可直接套用在既有資料上，不需重建資料表。
- **D1 查詢預算**：設定異動仍是一次 `SELECT *` 加一次 UPDATE，沒有新增查詢。
- **新舊客戶端混用**：
  - 舊版（v1.9.0 以前）的 `LocalFinanceDB` 以 `...raw.settings` 保留整個設定物件，存設定時會原樣帶回 `rebalanceTargets`。過期的寫入會被樂觀鎖版號擋下，進入衝突合併，不會覆蓋新值。
  - 舊版的 payload 若沒有 `rebalanceTargets`，伺服器沿用既有值。
- **伺服器輸入處理**：`normalizeRebalanceTargets` 會檢查 kind、截斷 key 與 label 長度、排除超出 0～100 的比例並去除重複。伺服器不檢查合計是否為 100%，但只影響該使用者自己的試算，可接受。
- **衝突合併**：`syncEngine.ts` 兩處設定合併都已加入 `rebalanceTargets`，`conflictUi.ts` 也補上欄位名稱。
- **匯入備份**：取代模式下，備份沒有該欄位時清為空陣列；合併模式沿用目前值。
- **XSS**：三個新 UI 檔只用 `innerHTML = ''` 清空容器。名稱、代號、分類、note、label 全部用 `textContent`；SVG 用 `createElementNS` 搭配 `setAttribute`，只放數值。
- **事件與記憶體**：沒有 document 或 window 層級的監聽，也沒有 ResizeObserver。監聽器都掛在每次重繪會重建的子元素上，不會累積。
- **只重繪目前分頁**：只從 `renderAssetsTab` 與 `renderStocksTab` 呼叫；觀察清單子分頁會隱藏三張卡片。
- **隱藏金額**：金額、Y 軸刻度、柱狀數值、aria-label、儲蓄率、覆蓋率、期間變化百分比都有遮罩（例外見 4-3）。
- **邊界**：
  - 無資料時卡片隱藏；只有 1 期時，折線圖只畫點，堆疊圖改畫單根長條。
  - 全部為 0 時以 `max(…, 1)` 避免除以 0；`deltaPct` 為 null 時不顯示 NaN；負淨資產時有處理基準線。
  - 已刪除的資產、交易、現金流都有排除；匯率無效時退回 32.5。
- **再平衡計算**：「只買不賣」的水位填補實測正確，投入金額全部分配給偏低的類別，不建議賣出；整數分配以最大餘數法使總和精確等於投入金額。
